# 08 画像生成（Codex CLI・OpenAI の Image API・Nano Banana）

Mittler では、「動画化予定」の開始・終了の絵と、素材の絵（`python .mittler/api.py . gen-image`）を生成できます。エンジンは Codex・OpenAI・Nano Banana の 3 つです。
作品の既定エンジンはタイムラインの `settings.image_engine` で決めます（作品づくりの最初にユーザーに聞いて決定）。絵の欄の `engine` や API の `--engine` で、ほかのエンジンも呼び出せます。キャラの参照には `@import char(id) as 名前;` を使います。

> **使い分けの目安**
> - 新しい絵の生成は OpenAI（GPT Image 2.5）、部分の直しは Nano Banana Pro が向いています。
> - 直した絵をさらに直して重ねると、細部が強調されすぎたノイズが出ます。部分の直しは Nano Banana Pro を使うか、元の参照（立ち絵・最初の参照・基準の全景）を参照し直して作り直してください。

## Codex CLI の画像生成
- **道具**：`tools/codex_jobs.py`（アダプタ）→ `tools/gen/codex_image.py`。`codex exec` の内蔵画像生成を 1 回呼び出し、できた画像を指定の場所に写します。読み取り専用のサンドボックスで動作し、1 枚 1〜2 分かかります。
- **セッションの継続**：**同じ場所・同じ作品は同じセッションで続けて作ります**（作品ごとの Codex セッション `work/codex-session.json`）。人の向き・小物・背景がそろい、差し戻しも「前の絵を保ったまま直す」形で効きます。同じセッションを同時に 2 つ動かしてはいけません。
- **参照画像の渡し方**：**画像生成の `referenced_image_paths` で渡します**（最大 5 枚）。添付しただけでは Codex が見るだけで画像生成には届きません。出力の `refs_ok` が `true` か必ず確認してください（`true` でなければ参照なしで生成されています）。
- **画風プロンプトの保持**：Codex は画像生成に渡す際にプロンプトを短い英語へ要約し、画風を落としやすい傾向があります。「画像の仕様を一字一句そのまま渡す」よう指示し、届いた割合 `spec_coverage` を確認します。0.9 未満は作り直してください（画風が落ちると表情や顔のかわいさも落ちます）。

## OpenAI の Image API（Codex とは別口）
- **道具**：`tools/openai_image_jobs.py`（アダプタ）→ `tools/gen/openai_image.py`（標準ライブラリのみ）。
  - 参照なし：`/v1/images/generations`
  - 参照あり：`/v1/images/edits`（multipart の `image[]`、16 枚まで）
- **モデル・品質の優先順**：絵の欄の `model`・`quality` → 設定 `mittler.openai.imageModel`・`imageQuality` → 既定は `gpt-image-2.5-sunburst`・`high`。
- **モデル名**（2026-11 の公式資料）：素の `gpt-image-2.5` はありません。
  - `gpt-image-2.5-sunburst`（基本・既定）
  - `gpt-image-2.5-flare`（小さく速い）
  - その他：`gpt-image-2`・`gpt-image-1.5`・`gpt-image-1-mini`
- **大きさ**：両辺 16 の倍数・アスペクト比 1:3〜3:1。2560×1440 より大きいサイズは試し扱いのため使いません。動画の比のまま動画より小さくならない大きさを選びます（例：1920×1080 → 2048×1152）。
- **品質 `quality` と出力**：`auto`・`low`・`medium`・`high`（既定）・`xhigh`・`max`（`xhigh`・`max` は 2.5 のみ）。出力形式は PNG、使用量は出力の横の `<絵>.openai.json` に記録されます（鍵は書きません）。
- **参照**：会話は続かないため、人物や背景をそろえたいときは参照（`@import char(…)`・`frame(…)`・`image(…)`）で渡します。
- **鍵・リトライ・確認**：鍵は `ps:OPENAI_API_KEY`（Windows の資格情報マネージャー。環境変数が優先）。429・5xx・接続不可のときのみ 3 回までリトライし、鍵の間違いは即停止します。動作確認は `tools/smoke_openai_image.py`（偽のサーバー。本番には送信しない）。

## Nano Banana（Gemini の画像生成）
- **道具**：`tools/gemini_image_jobs.py`（アダプタ）→ `tools/gen/gemini_image.py`（標準ライブラリのみ）。
  - `POST /v1beta/models/<モデル>:generateContent`（ヘッダ `x-goog-api-key`）に、文と参照画像（`inline_data`、14 枚まで）、および `generationConfig: {responseModalities: ["IMAGE"], imageConfig: {aspectRatio, imageSize}}` を送信します。
- **モデル**：名前を書けばほかのモデルも呼び出せます。
  - `gemini-3-pro-image`（Nano Banana Pro。最上位・既定）
  - `gemini-nano-banana-2.1`
  - `gemini-3.1-flash-image`（Nano Banana 2）
  - `gemini-3.1-flash-lite-image`（2 Lite）
  - `gemini-2.5-flash-image`（初代。解像度を選べないため `imageSize` を送らない）
- **解像度・アスペクト比**：解像度は `1K`・`2K`（既定）・`4K`。縦横比は `1:1`・`2:3`・`3:2`・`3:4`・`4:3`・`4:5`・`5:4`・`9:16`・`16:9`・`21:9` から動画に最も近いものを選びます（実測では 16:9 の `2K` が 2752×1536、`1K` が 1376×768）。
- **設定の優先順**：
  - エンジン：絵の欄の `engine: "nanobanana"`（API の `--engine`）→ 作品の既定 `settings.image_engine`
  - モデル・解像度：絵の欄の `model`・`quality`（解像度）→ 設定 `mittler.gemini.imageModel`・`imageSize` → `gemini-3-pro-image`・`2K`
- **出力と参照**：
  - 返ってくる画像は JPEG です（PNG を要求する欄はなく、指定すると 400 で拒否された）。Pillow で PNG に変換します（その Python に無ければ描く Python で変換）。
  - 考えている途中の絵（`thought: true`）は使いません。使用量は出力の横の `<絵>.gemini.json` に記録されます（鍵は書きません）。
  - 会話は続かないため、そろえたい要素は参照で渡します。
- **鍵・リトライ・確認**：鍵は Gemini TTS と同じ `ps:GEMINI_API_KEY`（資格情報マネージャー。環境変数 `GEMINI_API_KEY` が優先）。429・5xx・接続不可のときのみ 3 回までリトライします。動作確認は `tools/smoke_gemini_image.py`（偽のサーバー）。

## 生成した絵の扱い（どのエンジンでも）
- **生成したら必ず絵を読み戻して見る**：出力したファイルを開き、参照・基準の全景・前のカットと並べて確認してから使います。見ていない絵は採用しません。
- **人物の配置を確かめる**：頼んだ人数・位置・大きさ・構図か、参照どおりの人物（顔・髪・服）か、画面の外に切れていないか。
- **手と指を拡大確認する**：指が 6 本などの破綻は縮小した絵では見逃すため、手を 1 つずつ拡大（切り抜き）して指を数えます。手・腕の数、物の持ち方も見ます。
- **向きを確かめる**：顔・体・視線の向き、左右（右手・左手、持ち手、髪の分け目や服の打ち合わせ。左右の反転）、頼んだ向きになっているか。
- **まちがいがあれば作り直す**：部分の修正は Nano Banana Pro で、直しを重ねない（AI 用ガイドの 0）。動画化予定の絵のまちがいは、生成した動画にそのまま引き継がれます。
- **字幕用の空きを作らせない**：動画用の絵に下のぼかし・帯・余白を入れず、下端まで自然な場面にします。
- **服の文字を残す**：「文字・ロゴを入れない」と書くときも、キャラの服のデザインとしての文字は残します。プロンプトには「◯◯は服のデザインなので入れる。それ以外の文字・ロゴは入れない」と明記します。
- **軽い素材づくりにも活用する**：絵の生成は軽いため、部分的な素材（グレイン・テクスチャ・一部だけ動かす絵・エフェクトの中の絵）にも積極的に使ってかまいません。デザインが決まらないときは画面まるごとの見本を作って比較し、良いものを作品の中で再現します。
- **分担**：素材の生成と収集は、できればサブエージェントに任せ、本体は組み立てと画面確認に集中します。

## キャラの参照
- キャラの立ち絵・設定・声を作品の `characters.json` にまとめておくと、絵の参照（`@import char(id) as 名前;`）と TTS の声の両方で使えます。
- プロンプトは「変えない芯」（キャラの見た目・画風）と「カットごとに変える箇所」（場面・ポーズ・表情）に分けて書き、実際に送った全文を残しておきます（あとで同じ絵を作り直せるようにするため）。

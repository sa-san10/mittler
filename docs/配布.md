# 配布（VSIX の作り方・版の上げ方・置き方）

Mittler を人に渡したり別の PC に導入したりするための、**配布版**（中身をすべて同梱した VS Code 拡張＝VSIX）の作り方をまとめています（2026-11-13〜）。

- 導入する側の手順：[インストールガイド](インストールガイド.md) の 2（配布版を入れる・開発版との入れかえ）と 3（初期設定）
- **どこに出すか（GitHub の Releases・Marketplace・Open VSX）は持ち主が決めます。** この文書は手順と、公開時に必要な項目の一覧です。

## 1. 配布版と開発版

| 項目 | 配布版（VSIX） | 開発版（リポジトリを読む入口） |
|---|---|---|
| 作り方 | `python tools/build_vsix.py` → `dist/mittler-<版>.vsix` | `python tools/install_vscode.py`（作成してそのまま導入） |
| 中身 | 拡張・サーバー・編集画面・エンジン・部品・道具・ひな形・文書・初期設定・スキル（すべて同梱） | 入口 `loader.js` と `package.json` のみ（本体は clone したリポジトリの `extension.js`） |
| 動く場所 | VS Code の拡張の置き場（`%USERPROFILE%\.vscode\extensions\sa-san10.mittler-<版>\`）。リポジトリは不要 | clone したリポジトリ |
| 直したとき | 新しい VSIX を作って入れ直す（置き場ごと入れ替わる） | ウィンドウの再読み込みのみ（`package.json` を変えたときだけ入れ直す） |
| 向いている人 | 使う人（作品を作る）・人に渡すとき | Mittler 本体を直す人 |

拡張 ID はどちらも `sa-san10.mittler` です。片方を入れるともう片方は置き換わります（同じ PC に両方は入りません）。

### 配布版の決まり（`tools/smoke_package.py` で検証）

- **拡張の置き場は読み取り専用**：動作中に置き場の中へ何も書き込みません（`__pycache__`・キャッシュ・ログ・一時ファイル・`work/` を含む）。
  - サーバーは子プロセス（描画・書き出し区間・ジョブ係・TTS・アダプタ・解析）へ環境変数 `PYTHONDONTWRITEBYTECODE` を渡し、各種ツールや Blender 内の実行係も `__pycache__` を書きません。
  - 書き込み先は、作品フォルダ内・VS Code 拡張の保存場所（`globalStorage`：初期設定の venv）・一時フォルダのみです。
- **作品に Mittler の絶対パスを書かない**：配布版の置き場はバージョン番号付きで更新のたびに変わるため、PC ごとの情報（Mittler の場所・AI 用ガイドの写し・中継）は作品を開くたびに状態フォルダ `.mittler/` へ書き出します（インストールガイドの 4）。
- **配布版の印**：置き場の根にある `mittler_build.json`（版・コミット）が配布版の印です。開発版にはありません。
- **外部パッケージは同梱しない**：Python パッケージ（numpy・OpenCV・Pillow、3D なら moderngl）は PC・Python バージョンごとに異なる大きな依存のため VSIX に含めず、コマンド「Mittler: 初期設定」を押したときだけ導入します。ffmpeg・Python・Git・Blender も同梱しません（入れ方の案内のみ）。

## 2. VSIX を作る

```
python tools/build_vsix.py                  dist/mittler-<版>.vsix を作る（SHA-256 も表示）
python tools/build_vsix.py --list           入れるファイルの一覧とサイズだけ表示
python tools/build_vsix.py --out <ファイル>   出力先を変更
```

- **依存ツール**：Python の標準ライブラリのみで動作します（Node・npm・vsce は不要、どの Python でも可）。
- **対象ファイル**：**git に登録されているファイル**（`git ls-files`）のうち、下の表で「入れる」ものを現在の作業ツリーの内容で同梱します（未コミットの変更も含まれ、その場合は印の `dirty` が `true` になります）。
  - 新しく追加したファイルは `git add` してからビルドしてください。
  - git リポジトリでないフォルダ（git の無い写しなど）から作るときは、フォルダ内のファイルから同じ規則で選びます（印の `commit` は空）。
- **再現性**：同じ内容なら同一の VSIX が生成されます（ファイル順・タイムスタンプ・圧縮を統一）。`dist/` は git 管理外です。
- **作成後の検証**：`<描画の python> -X utf8 tools/smoke_package.py` を実行します（VSIX を作って展開し、展開先だけでサーバー・描画・書き出し・新規作品・フック・初期設定コマンドが動くか、置き場への書き込みや作品内の絶対パスが無いかを確認）。作成済みの VSIX を直接検証する場合は `--vsix dist/mittler-<版>.vsix` を付けます。

### 同梱対象の一覧

| 対象 | 配布版に | 理由 |
|---|---|---|
| `extension.js`・`extension_setup.js`・`package.json`・`package.nls*.json`・`README.md`（英語）・`README.ja.md`・`AGENTS.md`・`CLAUDE.md` | 入れる | 拡張本体・表示文言・入口の説明 |
| `LICENSE`・`THIRD_PARTY_NOTICES.md`・`images/icon.png` | 入れる | ライセンス（MIT・sa-san10）・同梱物のライセンス表示（同梱するのは下の Lucide アイコンのみ）・拡張アイコン（128×128） |
| `server/`・`editor/`・`pyengine/` | 入れる | サーバー・編集画面・描画エンジン |
| `editor/icons/`（`*.svg`・`LICENSE-lucide.txt`） | 入れる | 編集画面のアイコン。**Lucide**（https://lucide.dev 、版 1.65.0、ISC。Feather 由来は MIT）。npm registry の `lucide-static-1.65.0.tgz`（SHA-256 `d775e477…ba630`、registry の sha512 と一致）から使用分のみ改変せずコピー。ライセンス本文は配布物の `LICENSE` をそのまま同梱。追加時は同じ版からコピーし `editor/editor.css` の一覧に 1 行追記（`tools/smoke_icons.py`） |
| `effects_lib/common/`・`effects_lib/beatfx/` | 入れる | 新規作品に配る部品・「部品の置き場」・拍の演出（作品に依存しない部品） |
| `effects_lib/false_maria/`・`effects_lib/library.json` | 入れる | 偽マリアのエフェクト集（偽マリアMV のエフェクトのうちコードのみで描く 5 本と、人マスク無しでも使えるようにしたハート。「部品の置き場」へ提供）と、置き場に出すフォルダ一覧 |
| `tools/`（実行時ツール：`new_project.js`・`mittler_state.py`・`mittler_api.py`・`jobs.py`・アダプタ・`tts_gen.py`・`gen/`・`make_proxy.py`・`fix_hooks.py`・`av_ai_check.py`・`mittler.cmd`・`enhance.cmd`） | 入れる | サーバー・フック・エージェントが実行 |
| `tools/smoke_*.py`・`tools/calc_cli.js` | 入れない | 検証用（リポジトリ内で実行） |
| `tools/install_vscode.py`・`tools/build_vsix.py` | 入れない | 開発用ツール |
| `templates/`（`project/`・`state/`・`3d/`） | 入れる | 新規作品のひな形・`.mittler/` の中継・Blender 場面のひな形 |
| `docs/` | 入れる | AI 用ガイドの写し（`.mittler/guide.md`）の元・エージェントが読む文書 |
| `setup/`・`skills/` | 入れる | 初期設定チェック・Claude Code スキル |
| `server/defaults.author.json` | あれば入れる | その PC の置き方の既定値（インストールガイドの 12 の「既定の場所」）。作者のリポジトリから作る VSIX には入り、公開用の中身には無い |
| `work/`・`_trash/`・`dist/`・`.git` | 入れない | 作業ファイル |

- **サイズの目安（0.4.0）**：ファイル約 150〜165 個、圧縮後約 0.8 MB（圧縮前約 2 MB）。
- **公開向けメタデータ（0.4.0〜）**：ライセンスは MIT、作者は GitHub と同じ `sa-san10`。`package.json` には `"license": "MIT"`・`author`・`icon`（`images/icon.png`）・`repository`・`homepage`・`bugs` を設定済み（`"private"` は削除）。
  - `repository`・`homepage`・`bugs` は公開用のリポジトリ（https://github.com/sa-san10/mittler）を指しています。
- **初回起動通知**：拡張は VS Code 起動完了後（`activationEvents` の `onStartupFinished`）にも起動し、その版で初回のときだけ短い確認と通知を出します（インストールガイドの 3）。

## 3. 版を上げる

1. `package.json` の `version` を上げます（例：`0.3.0` → `0.3.1`。修正のみなら 3 つ目、機能追加なら 2 つ目）。VS Code は同じ版の VSIX でも `--force` で入れ直せますが、版を変えたほうが導入済みの版を判別しやすくなります。
2. 検証を実行します（[AI 用ガイド](スターターガイド（AI用）.md) の 7。少なくとも `tools/smoke_text.py`・`tools/smoke_docs.py`・`tools/smoke_package.py`）。
3. コミットしてから `python tools/build_vsix.py` を実行します（印の `commit` が最新コミットになり、`dirty` が `false` になります）。
4. 必要であればタグを打ちます（任意）：`git tag v<版>` → `git push origin v<版>`。

## 4. 渡す・置く

### GitHub の Releases（まずはこれ）

```
gh release create v<版> dist/mittler-<版>.vsix --title "Mittler <版>" --notes "変わったこと"
```

- リポジトリが非公開の場合、閲覧・ダウンロードできるのはリポジトリへのアクセス権がある人だけです。
- **受け取った人の手順**：VSIX をダウンロードし、VS Code の「拡張機能」→ 右上の「…」→「VSIX からのインストール…」（または `code --install-extension mittler-<版>.vsix`）→「Mittler: 初期設定」を実行します（インストールガイドの 2・3）。更新も同じ手順で置き換わります。

### VS Code Marketplace・Open VSX（出すと決めたとき）

**Marketplace への公開は延期中です。** 以下は公開すると決めたときのための備忘録です（出すかどうか・名前・発行者は持ち主が決めます）。

- **0.4.0 で準備済みのもの**：ライセンス（MIT）・`LICENSE`・アイコン・`repository`・英語の `README.md`。
- **延期に合わせて未追加のもの**：`keywords`・`categories`（現在は `Other` のみ）・`galleryBanner`・目録（`extension.vsixmanifest`）の Marketplace 用項目（ライセンス・アイコン・リポジトリのリンク）。

公開前に実施すること：

- **発行者の登録**：
  - Marketplace：発行者（`publisher`、現在は `sa-san10`）の登録と Azure DevOps の個人用アクセストークン。
  - Open VSX：Eclipse アカウント・発行者同意・名前空間・トークン。
  - トークンは鍵情報のため Windows の資格情報マネージャーなどに保存し、ファイルや画面に出さないこと。
- **`package.json` と目録の整備**：
  - `keywords`・`categories`・`galleryBanner` を追加する（`license`・`icon`・`repository` は 0.4.0 で済み。`repository` は公開用リポジトリへ書き換える）。
  - 目録に `<License>`・`<Icon>` と、ライセンス・アイコン・リポジトリリンクの Asset／Property を追加する（`tools/build_vsix.py` の `manifest_xml`）。
  - `README.md`（英語）が Marketplace の説明ページになります。詳しい文書は日本語（`README.ja.md`・`docs/`）です。
- **公開コマンド**：Marketplace は `vsce publish --packagePath dist/mittler-<版>.vsix`、Open VSX は `ovsx publish dist/mittler-<版>.vsix`（どちらも Node の道具で `npx` で実行可能）。`vsce` を使う場合でも、対象ファイルの選定を 1 か所に保つため `tools/build_vsix.py` で作った VSIX を渡します。
- **対象 OS の明記**：**Windows 専用**であること（インストールガイドの 12 の終わり）を説明に明記します（Marketplace 側では対象 OS を絞れないと推測されるため、公開時に確認すること）。

## 5. 既定の場所の入った VSIX と、入っていない VSIX

ビルド元のリポジトリに `server/defaults.author.json`（その PC の置き方の既定値。インストールガイドの 12 の「既定の場所」）があるかどうかで、VSIX の既定の探索先が少し変わります。

| 項目 | 既定の場所の入った VSIX（作者のリポジトリから作成） | 入っていない VSIX（公開しているもの） |
|---|---|---|
| 描く python・ffmpeg・Blender・解析の python | 設定が空なら、`defaults.author.json` に書いた場所（あれば）→ PATH | 設定が空なら PATH（描く python は「Mittler: 初期設定」で導入したものが設定に書かれる） |
| 解析モデルの置き場 | `defaults.author.json` に書いた場所 | ホームの `.cache/mittler/av_ai_models` |
| マスター書き出しの Real-ESRGAN・RIFE | 書いた場所 | 設定 `mittler.master.esrgan`・`mittler.master.rife` に記述 |
| キャラ設定のプリセット・H3 受け渡しドライブ | 書いた場所（あれば） | 設定・環境変数で指定（無ければ使えない旨の理由を表示） |
| それ以外（中身・絵・作品の形） | 同じ | 同じ |

どちらの VSIX でも、VS Code 設定（`mittler.*`）に明示した値が優先されます。既定の場所は「どこを探すか」を変えるだけであり、描かれる絵は同じです。

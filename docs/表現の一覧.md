# Mittler でできる表現の一覧

Mittler で使える表現の機能を 1 枚にまとめた入口です。詳しい書き方は各行の「くわしく」を参照してください。

- **人**：編集画面での操作
- **AI**：エージェント（Claude Code など）がファイルを書く、または `python .mittler/api.py . <コマンド>`（下の表では `api` と略記）で実行
- **API の網羅範囲**：**人がボタンで押していた操作は、Suno の採用と H3 の動画の生成のほかは、全部 API でも頼めます**（ボタンと同じ計算・同じ結果。2026-11-15。一覧は AI 用ガイドの 7.53）。
- **依存ツールの不足時**：「要るもの」が無い PC では、その機能は理由を出して止まります（黙って抜かしません）。

> **作品を作るときは、まず AI 用ガイドの 0「作品づくりの進め方」**（プラン → 骨格 → 生成と採用をユーザーと → 緻密な制作 → 最後の調整）。発想のたねは下の 8.5「組み合わせの例」を参照してください。

## 1. トラックとクリップ（タイムラインの基本）

| 表現 | 中身 | 使い方 | くわしく |
|---|---|---|---|
| 映像・画像 | 動画・静止画を並べる。切る・伸ばす・重ねる | **人**：アセット窓から置く・道具のバー（選択・カット・スリップ・分割・リップル削除）<br>**AI**：映像トラックにクリップを書く・`api place-video`（音もリンクして置く）・`api split`・`delete`・`ripple`・`gaps`・`stretch` | タイムライン形式「トラック」「クリップ（共通）」 |
| 画像の動き | 静止画をゆっくり寄る・動かす（カメラ） | **AI**：画像クリップのカメラの値 | タイムライン形式 |
| 速さ・時間の付け替え | 一定の速さ（`speed`）、曲線で速さを変える（`warp`） | **人**：映像の欄の速さ・グラフで点をドラッグ<br>**AI**：`speed`・`warp` | タイムライン形式「映像クリップの時間の付け替え」 |
| クリップの色 | クリップごとの色の手直し | **人**：右の欄の「色」 | タイムライン形式「クリップの色」 |
| カットごとの色（色の卓） | カットごとに明るさ・コントラスト・ビブランス・彩度 | **人**：右の「色」のタブ（色の値は人が決める。AI は頼まれたときだけ） | エフェクト `grade` |
| 字幕 | 位置・書体を決めて文字を出す | **人**：字幕トラック・「セリフから字幕を作る」<br>**AI**：字幕クリップ・`api subs-from-lines` | エフェクト `subtitle` |
| 字幕を ASS で焼く | 縁・影・ふりがななどの凝った字幕（libass） | **AI**：`settings.subtitle.renderer = "ass"` | タイムライン形式「字幕を ASS で焼く」 |
| 重ね絵 | 透明の PNG（フキダシ・描き文字・ロゴ）を出し方つきで | **人・AI**：エフェクト `sprite` を置く | エフェクト `sprite` |
| フェード | 黒から明ける・黒へ | エフェクト `fade` | エフェクト `fade` |
| 音・効果音・音楽 | 音のトラック。音量・フェード（曲線も） | **人**：音のトラックに置く<br>**AI**：音のクリップ・動画の音は `api video-audio` | AI 用ガイド 8 |
| カット・ト書き | タイムラインのメタデータ（カットの区切り・メモ） | **人**：カット・ト書きの段をダブルクリック・境目のドラッグ<br>**AI**：メタデータを書く・`api cut-split`・`cut-join`・`cut-rename`・`cut-edge`・`cut-align`（映像をカットに合わせる）・`cut-from-clip` | タイムライン形式「メタデータ」 |

## 2. 声とセリフ（TTS）

| 表現 | 中身 | 使い方 | 要るもの |
|---|---|---|---|
| セリフの声 | キャラの声でセリフを読む。テイクを何回も作って選べる。生成後の速さ（`tempo`）。同じトラックの次のセリフと重なると印 | **人**：「キャラ」タブでキャラを作る → TTS トラックに文を書いて「生成」（まとめては「未生成のセリフを全部生成」）<br>**AI**：TTS クリップ（キャラ・文）を書いて `api tts <セリフ> [--tempo 1.15]`・`api tts-all --wait`・テイクを選ぶ `api tts-take`（Gemini TTS は事前の許可があれば好きなときに・リトライも可） | Gemini TTS の鍵、または VOICEVOX |
| 演技の指定 | 文の中の演技タグ（`[whispers]` など）と、そのシーンだけの演技 `delivery_style` | TTS のクリップの文・`delivery_style` | **`docs/GeminiTTSの演技タグ.md`**・AI 用ガイド 8 |
| 読み辞書 | 読みまちがいを直す | 作品の `pronunciation.json`（ユーザーが単語と読みを言ったときだけ足す） | — |
| キャラのプリセット | 名前・立ち絵・声の設定をまとめて入れる | **人**：「キャラ」タブの「＋プリセットから」<br>**AI**：`api presets`・`api preset-add <id>` | プリセットの置き場（設定 `mittler.presetsDir`） |
| セリフから字幕 | セリフの文と時刻から字幕を作る | **人**：「セリフから字幕を作る」<br>**AI**：`api subs-from-lines` | — |

## 2.5 キャラクターとリファレンス（参照）の再利用

同じキャラ・同じ場所・同じ画風を、画像・動画・声で何度でも使い回すための仕組みです。詳しくはタイムライン形式「キャラ設定」「plan」、AI 用ガイド 7.52・7.6 を参照してください。

### キャラ設定（作品の `characters.json`）に入れておくもの

| 項目 | 中身 | どこで使われるか |
|---|---|---|
| `id`・`name` | キャラの呼び名（`id` は英数字。参照の書き方で使う） | 参照・TTS のクリップ |
| `image` | 立ち絵（基本の 1 枚） | 画像・動画生成の参照画像。編集画面「キャラ」タブの絵 |
| `images` | 立ち絵の差分（`{"smile": "assets/characters/hana_smile.png", …}`。表情・衣装・ポーズ違い） | 参照で差分を名指しできる |
| `look` | 外見の文（髪・目・服・体つき。生成時にプロンプトへ足される） | 画像・動画の生成（無ければ `profile` を使う） |
| `profile` | 人物像・話し方 | AI が台本やセリフを書くとき・外見の文が無いときの代わり |
| `color` | キャラの色（編集画面のセリフの印） | 編集画面 |
| `tts` | 声の設定：Gemini（モデル・声・いつもの声の指示）と VOICEVOX（話者・速さ・高さ・抑揚・音量）、どちらを使うか | セリフの生成（TTS のクリップに声を書かなければこれが使われる） |

### 参照の書き方（動画化予定のクリップのプロンプトの頭に書く。CSS の `@import` 風）

| 書き方 | 送られるもの |
|---|---|
| `@import char(hana) as ハナ;` | キャラの立ち絵（参照画像）＋外見の文。プロンプトの中では「ハナ」と呼べる |
| `@import char(hana, smile) as ハナ;` | 立ち絵の差分（笑顔など） |
| `@import image("assets/images/room.png") as 部屋;` | 背景・小物などの画像を参照に（場所・物の見た目をそろえる） |
| `@import frame(start);`・`@import frame(plan_002, end);` | 自分やほかの動画化予定クリップの「始まりの絵・終わりの絵」を参照に（カットどうしをつなげる・同じ構図を保つ） |
| `@import style(anime-cel);` | 作品の `styles/anime-cel.md` の画風の文を省略せずに足す（全カットで画風をそろえる） |
| `@import audio("assets/voice/x.wav", 1.20s, 4.50s);`・`audio(tts_p01_s01_t01);`・`audio(here);` | 声の参照（動画のプロンプトだけ。口パクの動画 `ref2va` に使う） |

- 1 行に `;` で区切っていくつでも書けます。`@import` で始まらない行が本文です。名前のまちがい（無いキャラ・無い差分・無いファイル）は編集画面のプロンプト欄に理由が出ます（参照のチップ）。
- 動画の生成（H3）では、`char(…)` の画像が顔の参照（`ref_images`）になります。

### 画像生成エンジンの選び方と優先順位

画像生成エンジンは 3 つあります。**作品の既定は、作品ごとに最初にユーザーへ聞いてタイムラインの `settings.image_engine` に書きます**（AI 用ガイドの 0）。**ほかのエンジンも呼べる**ため、生成と直しで向き不向きに合わせて使い分けます（生成は GPT Image 2.5、直しは Nano Banana Pro。下の 8.5「表現のヒント」）。

- **決定の優先順位**：絵ごとの欄（`engine`／API の `--engine`）→ 作品の既定 `settings.image_engine` → PC の設定 `mittler.image.engine` → Codex

| エンジン | 参照画像上限 | モデル・品質（解像度） | 特徴・サイズ・鍵 |
|---|---|---|---|
| **Codex**（Codex CLI） | 5 枚 | — | 作品ごとに同じ Codex の会話を続けて使うため、同じ作品内で人物や背景がそろいやすい |
| **OpenAI**（OpenAI Image API、Codex とは別口。2026-11-15〜） | 16 枚 | モデル選択可（既定 `gpt-image-2.5-sunburst`、速い `gpt-image-2.5-flare`、`gpt-image-2`・`gpt-image-1.5`・`gpt-image-1-mini` など名前を書けば何でも）／品質 `auto`〜`high`〜`max`（`xhigh`・`max` は 2.5 のみ） | 動画の縦横比で 16 の倍数の大きさを指定（1920×1080 なら 2048×1152）。会話は続かないのでそろえたいものは参照で渡す。鍵は資格情報マネージャーの `ps:OPENAI_API_KEY`（課金あり。計画の OK 範囲で使用） |
| **Nano Banana**（Gemini の画像生成。2026-11-19〜） | 14 枚 | モデル選択可（既定 `gemini-3-pro-image`＝Nano Banana Pro、`gemini-nano-banana-2.1`・`gemini-3.1-flash-image`（Nano Banana 2）・`gemini-3.1-flash-lite-image`・`gemini-2.5-flash-image` など）／解像度 `1K`・`2K`（既定）・`4K`（絵の欄の `quality` に書く） | 縦横比は動画にいちばん近いもの（16:9 など）。会話は続かないのでそろえたいものは参照で渡す。透明 PNG は作れない（単色背景で頼んで抜く）。鍵は Gemini TTS と同じ `ps:GEMINI_API_KEY`（課金あり。計画の OK 範囲で使用） |

- **絵の欄の書き方**：
  - OpenAI：`start_frame: {engine: "openai", model: "gpt-image-2.5-flare", quality: "high", …}`
  - Nano Banana：`{engine: "nanobanana", model: "gemini-3-pro-image", quality: "4K", …}`
  - `engine` を書かなければ既定が使われます。
- **1 回だけ切り替える API**：`api image <予定> start_frame --engine openai --model … --quality …`

### 使い回し方

| 使い回し | やり方 |
|---|---|
| キャラのプリセット | 作者が用意したキャラ一式（立ち絵・差分・外見・声の設定・元の設定の文書）を、どの作品にも「＋プリセットから」で写せる（置き場は設定 `mittler.presetsDir`）。声の設定は元の設定の原文どおり。無いもの・未確認のものは空 |
| 作品から作品へ | `characters.json` と `assets/characters/` を写せば、ほかの作品でも同じキャラ・同じ声で使える |
| 画風 | 作品の `styles/<名前>.md` に画風の文を書いておき、どのクリップでも `@import style(名前);` |
| カットのつながり | 前のクリップの終わりの絵を次のクリップの始まりの参照に（`frame(…, end)`） |
| 採用した生成物 | 採用したテイク（絵・動画・声・曲）は作品の `assets/` に残るので、ほかのクリップの参照（`image(…)`・`audio(…)`）にも使える |

## 3. 生成（作品の外の AI に作ってもらう）

| 表現 | 中身 | 使い方 | 要るもの |
|---|---|---|---|
| 画像の生成 | 動画化予定クリップの「始まりの絵・終わりの絵」を作る | **人**：動画化予定トラックで「生成」・テイクを押して選ぶ（エンジン・モデル・品質も欄で）<br>**AI**：`api image <クリップ> start_frame [--engine codex\|openai\|nanobanana --model M --quality Q]`・`api frame-take`・止める `api job-cancel`・参照を見る `api plan-resolve`（計画の OK 範囲なら設置まで込みで自走してよい） | Codex CLI、OpenAI の鍵（`ps:OPENAI_API_KEY`）、または Gemini の鍵（`ps:GEMINI_API_KEY`。TTS と同じ） |
| 素材の絵の生成 | 動画化予定に限らない 1 枚：フィルムグレイン・テクスチャ・光の漏れ・一部だけ動かす絵・エフェクトの中で使う絵（粒子の形・3D の面・模様）・小物・画面まるごとのモック。**軽いので多用してよい（むしろ使う）**。デザインがキマらないときはモックを何案か作って見て、いいものを動画の中で再現する。一度に全部作らず作業に合わせて都度、できるなら生成と収集はサブエージェントに（AI 用ガイドの 0） | **AI**：`api gen-image assets/images/gen/<名前>.png --prompt …`（`--ref`・OpenAI なら `--size`・`--background transparent`、Nano Banana なら `--quality 1K\|2K\|4K`） | `--engine` か作品の既定 `settings.image_engine` のエンジン |
| 動画の生成（絵から動画） | 始まりの絵から動画を作る（H3 `fl2va`）。**1 本は 2〜6 秒に区切る**（長いと生成時間が跳ね上がる）。**基本は始まりの絵だけ**、動きはプロンプトにミリ秒の時刻でポーズと演出を細かく書く（AI 用ガイド 7.52）。終わりの絵は頼まれたとき・絵でつなぐときだけ | **人**：「動画化」（生成は Colab の許可ボタンを人が押す）<br>**AI**：`api video <クリップ>`（AI 用ガイド 7.52・7.53）。テイク選択・採用は AI も可：`api video-take`・`api adopt`・`api adopt-all --latest` | H3 の受け渡し（Google ドライブと Colab。人の許可ボタンが要る） |
| 口パクの動画 | 声に合わせて口が動く動画（H3 `ref2va`。歌向き） | 動画化予定クリップに声の参照を書く | 同上。技術集 07・07b |
| 音楽の生成 | Suno で曲を作る → 試聴 → 人が採用 → ダウンロード。**歌詞つき**（`music.lyrics` を書けば Custom）もインストも可 | **AI**：Claude Code の Suno の道具でテイクを作り `api music-take`<br>**人**：「▶ suno.com で聞く」→「採用」 | Suno（**エージェントに Suno の MCP がつながっていること**。無ければ導入を提案＝3.5 冒頭）。**1 回の生成で 2 本できる**（今の MCP は 1 本だけを頼めない。AI 用ガイド 7.56）。生成回数は計画の OK 範囲で、ダウンロード（採用）は人が押す |
| Suno のプロンプトの書き方 | タグを並べるより、**曲のイメージを自然な文でシンプルに**（2〜4 文）。**ボーカルありは歌の明瞭さを優先**と書く（歌がはっきり聞き取れる＝リリックも合う） | AI 用ガイド 7.56 | — |

## 3.5 Suno で作った曲から取れる情報（拍・構成・歌詞の時刻）

Mittler 経由（Claude Code の Suno の道具＝MCP）で作った曲は、Suno の解析が**無料**で使えます。取れるものと作品のどこに入るかをまとめます。詳しくは `docs/Suno受け渡し契約.md`、タイムライン形式「Suno の曲」を参照してください。

> **Suno の MCP がエージェントにつながっていないと、曲は作れません。**
> 曲を作る・解析を取る・採用の曲を取ってくるのは、Mittler ではなくエージェント（Claude Code など）の Suno の道具（MCP。道具名は `mcp__suno__…`）です。Mittler は受け取るだけです。
> - ユーザーが「Suno で曲を作って」と望んだら、**まず自分の道具に Suno の MCP があるかを確かめます**（Claude Code なら道具の一覧・ToolSearch で `suno` を探す）。
> - **無ければ、作り始める前に導入を提案します**：「Suno の MCP（`https://api.suno.com/mcp`）をこのエージェントに足して、suno.com のアカウントでサインインすれば、Mittler から曲を作れます。足しますか？」。
>   Claude Code では、ユーザー設定に HTTP の MCP として追加（例：`claude mcp add --transport http suno https://api.suno.com/mcp`）→ Claude Code を開き直す → 初回利用時にブラウザでサインイン（ユーザーが実施）。設定の書きかえとサインインはユーザーの OK をもらってから進めます。
> - **導入しない・できないときの代わり**：ユーザーがブラウザの `suno.com` で作った曲をダウンロードして `assets/` に置きます（拍・構成・歌詞の時刻は Suno から取れないため、Mittler の解析で取ります＝下の「ブラウザ版で作った曲」）。または、ライセンスが動画に合うほかの曲を使います。
> - 計画段階で Suno を使うつもりなら、骨格を作る前（制作手順の ① の段）にこれを確認しておきます（生成の段で止まらないようにするため）。

| 取れるもの | Suno の道具 | 中身 | 作品のどこに入るか |
|---|---|---|---|
| 拍 | `audio-analysis` | 全部の拍の時刻と、小節の中の位置（1〜4。1 が小節の頭） | テイクの `analysis.beats`（`[曲の秒, 位置]`）。**採用すると**メタデータの `beats`「ビート（Suno・…）」に入る → 音ハメ・スナップ・エフェクトの拍（`ctx.beats`・`hits`）がそのまま効く |
| テンポ・拍子・キー | `audio-analysis` | `bpm`・`time_signature`・`key`（例 `"A major"`。取れないと `null`） | テイクの `analysis` |
| 曲の構成 | `audio-analysis` | 区間（`start`・`end`・`label` A・B・C…）。**同じ `label` は同じ素材のくり返し＝くり返す `label` はたいていサビ** | テイクの `analysis.sections`。採用するとメタデータの `song_sections`「曲の構成（Suno・…）」→ カットの区切り・場面の切り替えの目安に |
| 音の説明 | `audio-analysis` | `terms`・`labels`（楽器・雰囲気の言葉。例 `instrumental`・`piano`・`lo-fi`） | テイクの `analysis` |
| 歌詞 | `audio-retrieve`（と生成時の歌詞） | 歌詞の全文（`[Intro: …]` `[Chorus: …]` のような構成のメモつき） | クリップの `music.lyrics`・サイドカー |
| 歌詞の単語ごとの時刻 | `audio-lyrics-alignment` | 歌う単語ごとの時刻（カラオケ・字幕向け）。うまく合わせられなかった単語は `success: false`（隣からの推定）。インスト曲は空 | AI がサイドカーの `lyrics_alignment` に入れて納品 → **採用すると**メタデータの歌詞（kind `lyrics`「歌詞の時刻（Suno・…）」。行ごと・`words` に単語の時刻・置けなかった単語は印）に入る（2026-11-15）→ リリック演出（字幕・動く文字）がそのまま使える |

### 使い方の例

- 小節の頭（位置 1）ごとにカットを切る・拍ごとに光らせる（`fm_edge_neon`・`bfx_*`）・映像の動きを拍に合わせる（音ハメ）。
- 構成の区間の頭で場面を変える。くり返す `label`（サビ）で 3D やハートを一番派手にする。
- 歌詞の単語の時刻で、歌詞の字幕・動く文字を歌に合わせる。

### 流れと決まり

1. AI が音のクリップの `music` にプロンプト（歌つきなら歌詞）を書く → ユーザーが OK → AI が生成（生成クレジットを消費。30 秒・1 曲で 5 ほど。**今の Suno MCP は 1 回で必ず 2 本**＝2 本ぶん。`clip_count` を受け付ける定義なら `clip_count: 1` を必ず渡す）。
2. AI が解析と歌詞の時刻（どちらも無料）を取得し、`create_args`（生成に渡した引数）と一緒にサイドカーへ入れて `api music-take` で納品 → 編集画面にテイクが出る（この時点では音のファイルを取らない。2 本目・`create_args` 無しは注意が出る）。
3. ユーザーが「▶ suno.com で聞く」で試聴 →「採用」（ダウンロード用クレジットを 1 つ消費。曲ごとに 1 回、一度払えば wav も mp3 も取得可）。
4. AI が wav を取得して納品 → クリップの音になり、拍・構成・歌詞の時刻がメタデータに入る。

- **ステム（歌・伴奏・楽器ごと）**：Suno から取得可能（`audio-stems-create`：`two`＝歌と伴奏・`twelve`＝12 パート。生成クレジットを消費するため先にユーザーの OK が必要）→ `api stems-place` でミュートした音のトラックに置く。歌だけ・ドラムだけを解析（拍・文字起こし）に使う、伴奏だけを別場面に使うなどに活用できます。Suno MCP が無ければ解析の「ボーカルと伴奏に分ける」（demucs）を使います。
- **ブラウザ版の `suno.com` で作った曲**：拍・構成・歌詞の時刻は取れません（Suno が `not_found` を返す）。曲の情報と歌詞（構成のメモ）までは取得可能です。ファイルはユーザーがダウンロードして `assets/` に置き、拍・文字起こしは Mittler の解析で取ります。
- **商用利用**：生成した曲の商用利用可否は Suno のプランと規約に依ります（公開前に確認してください）。

## 4. 解析（素材から情報を取る）

人はクリップを右クリック、AI は `api analyze <クリップ> <種類> [--wait]` で実行します。結果はメタデータ・素材として作品に入ります。要るもの：解析用の Python（設定 `mittler.analysis.python`）。

| 種類 | 対象 | 取れるもの |

| 拍を取る（librosa） | 音 | 拍・小節の時刻（音ハメに使う） |
| 文字起こし（whisper large-v3） | 音・セリフ | 言葉と時刻（歌詞・字幕の時刻合わせ） |
| ボーカルと伴奏に分ける（demucs） | 音 | ボーカル・伴奏の音 |
| 人のポーズ（YOLO11） | 映像・画像 | 体の点・顔の位置 |
| 人のマスク（YOLO11） | 映像・画像 | 人の形のマスク（人の後ろに文字・人のふちを光らせるなど） |

## 8.5 組み合わせの例（作品づくりの発想のたね）

エージェントは Mittler の機能を理解し、機能を組み合わせたり驚くような使い方を見つけたりしてクリエイティブを目指します。動画の中の 1 つの表現のために、Mittler の機能を複数検討してプランを立てます。1 つの表現を 1 つの機能で済ませず、下のように重ねて考えます（下はいずれも例。テーマに合うかを試して比べて決めます。進め方は AI 用ガイドの 0）。

### 表現のヒント（決まり）

- **リリック動画の歌詞は、フォントだけの表現を最優先**：特に理由がなければ、歌詞の後ろにマット・帯・箱・ぼかした背景を敷かない。読みやすさは書体・太さ・大きさ・置き場所（絵の空いた所・人物のマスクの後ろ）・縁取り・影・光・色・動きで作る。敷くのは頼まれたとき・意匠として決めたときだけ。
- **モーショングラフィックスで、イージング無し（等速の直線の動き）は禁止。すべての動きに緩急**：文字・図形・カメラ・3D・HTML のレイヤー・鍵の、出る・動く・止まる・消えるの全部に、イーズイン・アウト（cubic・expo・back・elastic・バネ）を入れる。ゆっくりした流れにも緩急を入れる（詳しくは AI 用ガイドの 0）。
- **字幕・リリックには、テーマに合った魅力的な OFL の書体をダウンロードして使う**：既定の書体のまま済ませない。Google Fonts などの OFL の書体から何案か選んで静止画で比べる。使う前にライセンスが OFL かと、日本語の字が全部あるかを確かめる。置き場は `assets/fonts/`（`OFL.txt` も一緒に）、出典と使い道は `work/research.md` に記録する（詳しくは AI 用ガイドの 0）。
- **画像の生成は GPT Image 2.5、画像の編集（部分の修正）は Nano Banana Pro（`gemini-3-pro-image`）が優れる**：Codex や GPT Image で直しを重ねると、細部が強調されすぎたノイズが出る。部分の修正は Nano Banana Pro で行う（直したい絵を参照に、直す所だけを文で指定）か、元のリファレンスを参照し直して作り直す。直した絵をさらに直して重ねない（詳しくは AI 用ガイドの 0）。

- **生成した絵は、必ず読み戻して確かめる**：出力したファイルを開いて、人物の配置（人数・位置・大きさ・参照どおりか）、手と指（1 つずつ拡大して本数を数える）、向き（顔・体・視線・左右・反転）にまちがいが無いかを見る。まちがいがあれば使わずに作り直す（詳しくは AI 用ガイドの 0）。

### 組み合わせの例

| 狙い | 組み合わせ（機能の名前） |
|---|---|
| ロゴ・タイトルの登場 | その場で書く GPU の立体の文字（`gl3d` の `sc.text`。組み上がる）× 拍のメタデータで組み上がりを拍頭に × `fm_light`（キラ・ブルーム）× `gl_lightrays`（下からの筋）。案を変えて Blender の金属のロゴ `blender3d`、`sprite`＋`bfx_text_shockwave` とも比べる |
| 画面の録画をかっこよく見せる | 録画の映像を `gl_cards3d` の板に貼る × 音ハメ（`onbeat`）の拍で板を回す・切り替える × `fm_edge_neon`（打ちで外周がネオン）× `bfx_beat_camera`（拍ごとの寄り・ダッチ） |
| 文字を人の後ろに通す | 解析の人のマスク（`mask`）× 字幕・その場で書く立体の文字を人の後ろの段に × `bfx_rim`（人の輪郭が光る）。人の切り抜き（`cutout`）を最前面に重ね絵 `sprite` で戻す手も |
| 曲の構成で場面を割る | Suno の曲の構成（kind `song_sections`。くり返す `label` はたいていサビ）でカットを割る（`cut-split`）× サビで 3D（`gl_particles3d`・`gl_cards3d`）とハート `fm_hearts` を最大に × 区間ごとの色 `bfx_grade_keys` |
| 歌詞を歌に合わせて見せる | Suno の歌詞の時刻（kind `lyrics` の `words`）か解析の文字起こし（`transcribe`）× 字幕の 1 語ずつの出し方・その場で書く立体の文字の 1 字ずつ × 強い語で `bfx_radial`（放射の残像） |
| 動きを拍に吸いつかせる | 生成した動画（H3）× 音ハメの自動（`onbeat`。動きの止まり・切り返しを拍に）× 拍で `fm_shutter_flash`（白フラッシュ）を要所だけ × 速さの曲線を手で追い込む |
| セリフをリズムの素材にする | TTS のテイク（`tempo` で速さをそろえる）を拍に置く × 字幕を拍頭で出す（`subs-from-lines` のあと時刻を拍に吸いつける）× 解析の拍（`beats`）で効果音を重ねる |
| カットのつながりを自然に | 動画化予定の参照 `@import frame(前のクリップ, end)` で前の終わりの絵を次の始まりに × `@import style(…)` で画風をそろえる × クリップの色（`grade`）で前後をそろえる・`fm_match` |
| 一つの世界観を通す | キャラ設定（`look`・差分の立ち絵）× `@import char(…)` を全部のカットに × 曲の歌詞（Custom）とセリフの演技タグ（`docs/GeminiTTSの演技タグ.md`）で同じ人物像に |
| 終わりを締める | 曲の終わりの構成の区間 × `fm_tail_credits`（暗転とクレジット）× `bfx_vignette` × 最後の拍で `gl_lightrays` を消す |
| 驚きを作る（目的の外の使い方） | 動画の音の取り出し（`video-audio`）で映像の環境音を BGM の下に敷く・解析の `stems` の伴奏だけを別の場面に使う・ビートのメタデータを拍以外（場面転換の目印）に使う・`gl_cards3d` に今の画面そのものを貼って画面が割れる演出 |

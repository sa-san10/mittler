Mittler（VS Code の拡張機能として動作する動画エディタ）の作品フォルダです（{{DATE}} 作成）。返答はユーザーの言語で、簡潔に書いてください。
人は編集画面から、エージェントはファイル編集から同じ作品を編集します（ファイルを書き換えると、編集画面が即座に再読み込みします）。

## 曲と歌詞を渡されて「MV 作って」と頼まれたら

Mittler の `docs/MVを作る（AI用）.md`（Mittler の場所は `.mittler/env.json`） のとおりに進めます：曲と歌詞の確認 → 最初の質問（主人公・キャラの素材・使う生成の要素・世界観）→ 企画書と絵コンテの PDF を見せる → **OK をもらってから制作**。どの機能・道具で作るかは指定されていないので、機能を研究して自由に選びます（ほかの AI に任せるときも、目的と決まったことを渡し、道具は指定しません）。

## 「○○ってテーマで動画を作って」と頼まれたら

**最優先で AI 用ガイド（`.mittler/guide.md`）の 0「作品づくりの進め方」**に従います（この手順が最も重要です）。

- **⓪ 事前確認**：最初に「プランができたら見せて OK をもらうか、そのまま進めてよいか」をユーザーに確認し（そのまま進める場合は使用量もここで確認）、回答を `work/research.md` の冒頭に書いてその方針どおりに進めます。画像生成を使う場合は、同じ最初の質問で「Codex か OpenAI か Nano Banana か」も聞き、回答をタイムラインの `settings.image_engine`（作品の既定）に書き込みます。ほかのエンジンも呼び出せるため、生成と修正で向き不向きに合わせて使い分けて構いません。
- **① プラン立案**：Mittler の `docs/表現の一覧.md` をすべて読んで機能を研究し、見せ場を決め、1 つの表現ごとに複数案・組み合わせを検討して試作・比較します。計画と概算の使用量をユーザーに見せて OK をもらいます（OK の範囲内は自由に使用して構いません）。
- **② 動画の骨格作成（AI 自走）**：画像生成と動画化予定の配置まで含めて骨格を組み上げます。生成を依頼する前に下準備をすべて終えておきます。
- **③ 動画・楽曲の生成と採用**：H3 の動画と Suno の曲の生成・採用をユーザーと一緒に進めます。
- **④ 細部の作り込み**：音ハメ・リリック演出・人物の切り抜き・生成動画の加工を、画面で確認しながら緻密に仕上げます。
- **⑤ 最終調整**：ユーザーと一緒に最後の調整を行います。

研究のメモは `work/research.md`（git 管理外）に記録します。

- **画像生成の積極活用（軽いので多用してよい）**：始まり・終わりの絵だけでなく、部分的な素材（フィルムグレイン・テクスチャ・一部だけ動かす絵・エフェクトの中で使う絵・小物）にも積極的に使います（`python .mittler/api.py . gen-image assets/images/gen/<名前>.png --prompt …`）。一度に全部作らず、作業に合わせて都度生成して構いません。可能であれば素材の生成と収集はサブエージェントに任せ（作品のフォルダ・エンジン・保存先・欲しいものをすべて渡して生成一覧を返してもらい）、本体が絵を見て確認します。
- **生成した絵は必ず読み戻して確かめる**：出力したファイルを開いて、人物の配置（人数・位置・大きさ・参照どおりか）・手と指（1 つずつ拡大して本数を数える）・向き（顔・体・視線・左右・反転）にまちがいが無いかを見ます。まちがいがあれば使わずに作り直します。
- **デザインが定まらないときはモックで検証**：画像生成で画面まるごとのモックを何案か作って確認し、良い案を動画プロジェクトの中で再現します（モック画像をそのまま貼って済ませない。保存先は `work/mock/`）。詳細は AI 用ガイドの 0 を参照してください。

## 「これ」「ここ」の見つけ方

話しかけられるたびに、フック（`.claude/settings.json` → `.mittler/hook.py`）が編集画面の現在状態（選択中のクリップ・時刻・映っている要素）を添えます。
詳細は `.mittler/state.json`、停止中のフレーム画像は `.mittler/current_frame.jpg` で確認できます。
ユーザーが画面に描いて「AI に渡す」を押した書き込みは、`state.json` の `annotations_pending` に載ります（フックの無い AI は自分で見る）。あれば `image`（描いた画面）を見て、その画面への頼みとして読み、見たら `annotation` の `annotation.json` の `delivered` を `true` にします。

## 決まり

- **文書の正しさ**：Mittler の文書（AI 用ガイド・この `AGENTS.md`）は完全な正しさを保証しません。作業中に、文書とコード・実際の動きとの不整合や誤りらしきものに気づいたら、調べて（コード・静止画・ログ・小さな試し）、誤りと分かったら**何がどう間違っていたか（どの文書のどの節・書いてあること・実際・どう調べたか）とどうしたいかをユーザーに伝えて確認し、許可をもらってから**、文書と違うやり方で進めたり、バグとして直したりします。許可なしに文書と違うやり方をしない・文書を書き換えません。
- **作業ごとのコミット（無断プッシュ禁止）**：ユーザーに特に指示がなければ、作業のたびにコミットします（`git add -A` → `git commit`。メッセージは日本語で作業内容を記述し、先頭に `AI:` を付ける）。作業開始前に `git status` を確認し、未コミットの人の変更があれば先にそれだけコミットして AI の変更と混ぜません。ユーザーの指示がある場合はそれに従います。**プッシュは依頼されたときだけ**行います。返答には「直した内容・コミットの短いハッシュ・戻すときは『戻して』と言えばそのコミットを取り消す（`git revert`）」旨を添えてください。
- **素材を上書きしない**：`assets/` は git 管理外で復元できません。必ず新しいファイル名で作成します。
- **開いているタイムラインを直接編集する**：**ユーザーに明示的に別の場所を指示されない限り、編集画面で開かれているこの作品のタイムラインを直接編集します**（写し・複製プロジェクトで作業すると、ユーザーが編集画面で AI の変更を確認できず困るため）。変更箇所は編集画面上部バーの「オート」により再生位置が飛んで光るため、ユーザーが画面で追えます。
- **写し（`*.test.cut.json`）の用途を限定する**：写し（git 管理外）を使うのは、壊れるおそれのある試作・Mittler の動作確認・ユーザーから写しで試すよう指示されたときだけです（作成時は一言伝えます）。正本タイムラインでテストは流しません。
- **人の編集中は待機する**：人が編集画面で編集している最中は待ちます（後から保存したほうが勝ち、先の保存は上書きされて消えるため）。そうでなければ開いている正本を直接編集します。
- **エフェクトに状態を持たせない**：エフェクトの描画は時刻・コマ番号・素材だけで決めます（前のコマを記憶しない。乱数は決まった種を使用）。3D を含む作品に限り、別の PC・GPU で画素がわずかに異なって構いません。
- **色の値を勝手に決めない**：色の卓・クリップの色は人が編集画面で決めます。依頼されない限り決めません。
- **生成使用量と外部操作の事前確認**：画像・動画・音楽・声の生成は、計画と一緒にざっくりの使用量（枚数・本数・回数）をユーザーへ提示して OK をもらい、その範囲内であれば自由に使用できます（範囲を超える場合は聞き直します）。Gemini TTS は事前許可があれば随時実行・リトライ可能です。Suno は 1 回の生成で 2 本生成されます（AI 用ガイドの 7.56）。Suno の採用（ダウンロード用クレジット消費）はユーザーが操作します。パッケージ導入は事前にユーザーへ伝えてください。
- **重い処理は常時見張りを付けて実行する**：重い処理（重いシーンの描画・書き出し・マスター・Blender・解析・まとめての生成）は必要であれば遠慮せず実行して構いません（画質・長さを勝手に落とさない）。その代わり**毎回、サブエージェント（または背景タスク）で独立に見張りを立て続けます**：`python <mittler_dir>/tools/watchdog.py --expect-min <見積もりの分> --log work/watch.log -- <コマンド>`（書き出しの場合は `-- <コマンド>` の代わりに `--on-stop "python .mittler/api.py . export-cancel"`）。経過時間・CPU・メモリ・スワップ・GPU を監視し、想定を超えた長時間の全力稼働やスワップの爆増などで停止します。**異常停止した場合はコードを確かめて修正 → 小さく試して再実行し、直せなければ止めたままユーザーに理由と記録を見せて許可を得ます**（毎回厳守）。見張りなしで実行しないでください。詳細は Mittler ルートの `AGENTS.md` の「重い処理」を参照してください。
- **管理対象外ファイルに触れない**：`.mittler/` 内のファイルおよび Mittler 本体（`mittler_dir`）のファイルは編集しないでください（拡張機能が上書きする・拡張機能更新時に入れ替わるため）。

# MV を作る（AI 用）

曲（音声ファイル）と歌詞を渡されて「MV 作って」と頼まれたときの進め方です。
この文書が決めているのは、**何をユーザーに聞き、何を見せて、どこで OK をもらうか**だけです。
どの機能・道具・手法で作るかは書いていません。表現と作り方は、あなたが Mittler の機能（`docs/表現の一覧.md` ほか）を研究して自由に選び、組み合わせてください。

## 流れ

1. 曲と歌詞を確かめる
2. 最初の質問（1 回にまとめて）
3. 企画書と絵コンテを PDF で作って見せる
4. OK をもらう（直しがあれば 3 に戻る）
5. 制作

**4 の OK をもらうまで、制作（作品の素材づくり・生成・タイムラインの組み立て）には入りません。**
1〜3 のための下調べ・試作（曲の解析、絵コンテ用の絵、表現の小さな試し）は構いません。生成を使うなら、2 で答えてもらった範囲の中で行います。

## 1. 曲と歌詞を確かめる

- 渡された曲と歌詞を、作品の中に置きます。
  - 曲：作品の `assets/music/` に写します。元のファイルは変えません。
  - 歌詞：チャットに貼られた文も含めて、**原文のまま** `work/lyrics.txt` に保存します（表記・改行・空行を直さない）。
  - 作品がまだ無いとき（空のフォルダなど）は、先に `docs/新しい作品を始める（AI用）.md` のとおりに作品を作ります。長さは曲に合わせ、画面の形が分からなければ 2 の質問で聞いてから作ります。
- 曲を聴いたものとして扱えるところまで調べます：長さ、テンポ、構成（イントロ・A メロ・サビ・間奏・アウトロなど）、盛り上がりの位置、歌詞がどこで歌われるか。
- 歌詞を読み、言葉・情景・感情・繰り返し・物語を読み取ります。
- 曲と歌詞が食い違う（歌詞の一部が歌われていない、順番が違うなど）ときは、2 の質問に入れて確かめます。
- 調べたことは `work/research.md` に書きます。

## 2. 最初の質問

研究や企画に入る前に、次をまとめて 1 回で聞きます（選びやすいように選択肢を出し、自由に書いて答えられるようにもします）。

1. **主人公と背景のビジュアル**：もう決まっているか。キャラクターの設定や立ち絵（テンプレート）はあるか。あるなら場所を聞きます。
   作品やその PC にあるキャラ（キャラのプリセットなど）が見つかれば、候補として見せます。
2. **使う生成の要素**：画像の生成・動画の生成・モーショングラフィックスだけ、またはその組み合わせ。
   生成を使うなら、**ざっくりの使用量**（画像の枚数・動画の本数くらい）と、企画書と絵コンテの段階で生成を使ってよいかも聞きます。
   画像の生成を使うときは、AI 用ガイドの 0 の決まりのとおり、絵のエンジンもここで聞きます。
3. **世界観と雰囲気**：歌詞から読み取った世界観の案を 2〜3 個（それぞれ一言のコンセプトと、色・質感・場所・時間帯・物語の短い説明）出して選んでもらいます。案を混ぜる・自由に書く、も選べるようにします。
4. **画面の形と用途**（分からないときだけ）：横長・縦長・正方形、どこに出すか。

答えは**原文のまま** `work/research.md` の頭に書き、そのとおりに進めます。答えが無い項目は、あなたが決めてよい所として企画書に「こちらで決めたこと」として書きます。

## 3. 企画書と絵コンテ（PDF）

2 つの PDF を作って、ユーザーに見せます。作り方（レイアウト・PDF にする方法）は自由です。読みやすく、スマートフォンでも読める大きさの字にします。

置き場：`work/plan/企画書_v1.pdf`・`work/plan/絵コンテ_v1.pdf`。作り直したら `_v2`・`_v3` と番号を上げ、前の版は消しません。PDF のもと（文章・絵）も同じフォルダに残します。

### 企画書に入れること
- 題（曲名）と、一言のコンセプト
- 世界観・雰囲気（2 の答え）、主人公とキャラクター
- ビジュアルの方向：色・光・質感・画面の密度・参考のイメージ
- 文字（リリック）の見せ方の方針
- 構成表：曲の区間ごとに、時刻・歌詞の頭・場面・見せ場・盛り上がりの強さ
- いちばんの見せ場（2〜3 か所）と、そこで何を感じさせるか
- 使う生成の要素と、ざっくりの使用量（2 の答えの範囲の中で）
- 制作の段取りと、途中でユーザーに見てもらう所
- こちらで決めたこと・まだ決まっていないこと・心配な所

### 絵コンテに入れること
カット（または短い区間）ごとに 1 コマ。各コマに：
- 番号、時刻（開始〜終了）、その間の歌詞
- 絵（構図と人物・物の位置が分かるもの。ラフでよい）
- 何が映っているか、カメラと動き、場面の切り替え
- 文字（歌詞）の出し方
- 音との合わせ（拍・サビの頭・ブレイクなど）
- そのカットの作り方の種類（生成した絵・生成した動画・モーショングラフィックス など。ユーザーが使用量を見積もれる程度に）

### 見せ方
- 2 つの PDF の場所を伝え、チャットに添付できる環境なら添付します。
- 企画の要点（コンセプト・見せ場・使用量）を短く書き、「この内容で制作に入ってよいか、直したい所はあるか」を聞きます。
- 直しを頼まれたら、版を上げて作り直し、どこを変えたかを書いて、もう一度見せます。

## 4. OK のあと：制作

- OK をもらった版（例：`企画書_v2.pdf`）を `work/research.md` に書きます。これが制作の基準です。
- 制作は AI 用ガイドの 0 の 2〜5（骨格 → 生成と採用 → 作り込み → 最後の調整）の流れで進めます。曲は渡されたものを使います（作り直さない・変えない）。
- 企画書と絵コンテの範囲の中なら、細かい表現・作り方は自由に変えて構いません。**見せ場・世界観・構成・使用量が変わるほどの変更**は、先にユーザーに見せて確かめます。
- AGENTS.md の決まり（生成の使用量・重い処理の見張り・素材を上書きしない・コミット）は、このモードでも同じです。

## 任せ方（サブエージェントなど、ほかの AI に仕事を渡すとき）

- 渡すのは、**目的・素材・決まったこと・制約**です：曲と歌詞のファイル、2 の答えの原文、OK をもらった企画書と絵コンテ、担当する範囲、使用量の上限、作品の決まり、置き場と名前。
- **どの機能・道具・手順を使うかは指定しません**。どう作るかは、任された側が自分で研究して選びます（それぞれの AI の判断と創造性を生かすため）。
- 決まったことは要約せず、原文やファイルのまま渡します。
- 返ってきたものは、自分の目で見て、企画と合っているかを確かめてから使います。

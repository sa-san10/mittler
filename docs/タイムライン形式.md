# タイムライン形式（`*.cut.json`）

作品フォルダに 1 つ置く JSON ファイルです。**これが作品の正本**であり、レイヤーの重なり順・開始時刻・長さはそのまま描画に使われます。

- 編集画面も Claude も、このファイルを直接編集します。編集画面はファイルの変更を監視し、自動で再読み込みします。
- 形式は **Python エンジン（`mittler/py1`）** のみです（`tools/new_project.js` で作成する作品）。
- 空の見本：`templates/project/project.cut.json`

# Python エンジン（`mittler/py1`）

描画エンジンは `pyengine/mittler`（numpy・opencv・Pillow）です。静止コマの描画は描画サーバー（`mittler serve`）、動画の書き出しは `mittler video` が担当します。

## いちばん外側

トップレベルのキー一覧です。詳細が長い `render` と `settings.*` は、表のすぐ下で項目ごとに解説します。

| キー | 必須/任意 | 中身 |
|---|---|---|
| `format` / `engine` | 必須（`format`） | `"mittler/py1"`・`"mittler"`（ファイル形式の識別子）。サーバーは `format` が `mittler/py` で始まることだけを見て、違えば開きません（`engine` は読みません）。前の名前の `"claude-cut/py1"` も同じ形として開きます（`server/names.js` の `formatOk`。新しく作る作品には書きません） |
| `name` | 任意 | 表示名 |

| `root` | 任意 | 素材の根（タイムラインからの相対パス。`"."` か `"base"`。省略時は `"."`）。クリップの `src` やエフェクトの画像は `root` からの相対パスになります |

| `settings` | 任意 | 音声・字幕・書き出し・キャッシュ・マスター・画像生成・デコードなどの作品設定（詳細は下の「`settings` の詳細」） |

### `render` の詳細

- `{python}`：描く Python の場所を指定します。VS Code の設定 `mittler.render.python` が無いとき、こちらを先に試します（起動前に確かめます：`docs/インストールガイド.md` の 11）。
- 2026-10-30 以降、新しい作品（`templates/project`・取り込み器）には書きません。書かれていなければ PC の設定か既定（`server/defaults.js`、一覧はインストールガイドの 12）で決まります。
- 前の作品に書いてある値はそのまま使います。
- 前の作品に残る `host`・`remote`（ssh モード。2026-10-30 に廃止）は使いません（サーバーがログに 1 度知らせます）。

### `settings` の詳細

`settings` の直下には以下の項目を置けます。これ以外のキーはエフェクトが独自に読みます（`tonemap` など）。

- `audio`: `{peak: 0.97, mixer}`
  - `peak`：書き出しの音の頭打ち。`null` なら頭打ちしません。
  - `mixer`：`"numpy"` を指定すると、下の「numpy の混ぜ方」を使います。
- `subtitle`: `{…}`
  - 字幕の既定の見た目。`renderer: "ass"` を指定すると、下の「字幕を ASS で焼く」を使います。
- `frame_time`: `true` にすると、時刻をコマ番号から `n / fps` に直して描きます（並列書き出しでも同じ小数になります）。
- `export` / `cache` / `master` / `image_engine` / `cuts_on_adopt` / `decode`：各詳細は以下のとおりです。

#### `settings.export`（書き出しエンコード）

省略時は `libx264`・`medium`・`crf 18`・ffmpeg 既定の色変換・AAC `256k`（偽マリアMV と同じ）になります。

- `video`: `{preset, crf, profile, colors: "bt709", threads, x264_params}`
  - `colors: "bt709"`：RGB→YUV を BT.709 の式で変換し、色の印（カラーメタデータ）も付けます。
  - `threads`：x264 のスレッド数。
  - `x264_params`：`"asm=…"` など。x264 は CPU の機能（AVX512 など）で結果が変わります。
- `audio`: `{bitrate, sample_rate}`
- `loudnorm`: `{I, TP, LRA, ffmpeg?}`
  - 書き出しの最後に音を 2 パスで正規化します（`pyengine/mittler/loudnorm.py`）。元のファイル `<名前>_premaster.mp4` も残ります。
- 元の作品の書き出しに合わせる設定例：
  - 作者のダンス動画：`slow`・`16`・`high`・`bt709`・`320k`
  - 作者の紙芝居の作品：`medium`・`18`・`threads 24`・`asm`・`192k`・`loudnorm` −16/−2/11

#### `settings.cache`（キャッシュ）

- `mask_mb`（任意、2026-10-30）：人のマスク PNG をデコードした結果のメモリ上限（MB、既定 `512`。`0` で覚えない。`pyengine/mittler/helpers.py` の `read_gray`）。書き出しの区間プロセスは `64` MB までです。
- `frames`（2026-11-16）：`false` で描いたコマを `work/cache/frames/` にためません（既定はためる。`pyengine/mittler/fcache.py`）。
- `frames_gb`（2026-11-16）：ためる上限（GB、既定 `40`。FHD の PNG で 1 コマ 3〜5 MB）。ディスクの空きが 20 GB を切りそうなら半分にし、超えたら古いものから消します。
- `settings.cache` 自体は、ためた絵のキャッシュ鍵に入りません。

#### `settings.master`（マスター書き出し、任意、2026-10-31）

マスター書き出しの作品ごとの設定です。

- `upscale`：映像素材を 4K に上げる Real-ESRGAN のモデルを選びます。
  - `"anime"`：アニメ（`realesr-animevideov3`）
  - `"real"`：実写（`realesrgan-x4plus`）
  - `"none"`：アップスケールなし（いつもの大きさのキャンバスで 60fps にするだけ。クリップの `upscale` は使わない。インストールガイドの 12「アップスケールなし（60fps だけ）」）
- 編集画面のマスター窓「画質」（標準＝`none`・高画質（アニメ）＝`anime`・高画質（実写）＝`real`）で選ぶとここに入ります。
- **書かれていなければ今までと同じ**です（PC の設定 `mittler.master.esrganModel`、既定 `realesr-animevideov3`＝アニメ）。クリップ側の `upscale` があればそちらが優先されます。
- 単体コマンドの `mittler master --upscale anime｜real｜none` はこの設定の代わりになります（クリップの `upscale` はそれでも効きますが、`none` のときは効きません）。
- モデルの倍率などの仕様は `pyengine/mittler/master.py` の `UPSCALE_KINDS`・`ESRGAN_MODELS`、詳しくはインストールガイドの 12「アップスケールのモデル」を参照してください。

#### `settings.image_engine`（画像生成エンジンの作品既定、任意、2026-11-15）

- この作品の動画化予定の絵を作るエンジンを指定します（`"codex"`・`"openai"`・`"nanobanana"`＝Nano Banana、2026-11-19〜）。
- 絵の欄の `engine`（API の `--engine`）が空のときに使う**作品の既定**です（PC の設定より優先）。ほかのエンジンも絵の欄で選べます（2026-11-19〜。以前は断っていました）。
- 編集画面のエンジン欄の「作品の既定」に対応します。AI は最初にユーザーに聞いて書きます（AI 用ガイドの 0）。

#### `settings.cuts_on_adopt`（任意、2026-10-31）

- `true` のとき、動画化予定の「採用」で予定クリップの範囲をカットにします（下の「カットとクリップの `cut`」）。編集画面の動画化予定の欄のチェックに対応します。

#### `settings.decode`（任意、2026-10-30）

- `hwaccel`：映像クリップを読む ffmpeg に `-hwaccel` を付けます（`"cuda"` など。既定なし＝CPU）。
- 出る絵は CPU と同じです（偽マリアの素材でビット単位の一致を確認済み）。GPU で読めなければ CPU に戻ります。
- 小さい素材（1344×768）では 1 回のシークが GPU のほうが 60〜120 ms 遅かった（GPU の準備の分）ため、既定はオフです。コマンドの `mittler … --hwaccel cuda` でも指定できます。

## トラック

```json
{ "id": "t_…", "name": "表示名", "kind": "…", "hidden": true, "muted": true, "clips": [ ] }
```
（`hidden`・`muted` は任意）

| `kind` | 中身 | クリップの `type` |
|---|---|---|
| `video` | 映像（絵の土台）。その時刻でいちばん上のクリップが映ります | `video`・`image` |
| `plan` | 動画化予定（映像トラックのすぐ下）。映像が無い時刻は、予定クリップのスタート→エンドの絵を仮に映します | `plan` |
| `effect` | エフェクト（`effects/<名前>.py`）。トラック自体に `effect` を書いてもかまいません | `effect` |
| `subtitle` | 簡易字幕（`effects/subtitle.py` が描きます） | `subtitle` |
| `tts` | セリフ（TTS）。`character`（キャラの id）を持ちます | `tts` |
| `audio` | 音。`role` は `sfx`（効果音）・`bgm`（音楽）・`reference`（参考。ふつう `muted`）。トラックの `gain`（dB）も加算されます。`from_video: true` は「動画の音」トラック（動画を置いたときに音を入れる先） | `audio` |

## 映像クリップの時間の付け替え（`warp`、音ハメ）

`warp` には 2 通りの形式があります。計算は `pyengine/mittler/warp.py` で行い、編集画面（`editor/warp.js`）・サーバーのサムネ・HTML の runtime も同じ計算を使います。

### 1. 点で指定する形式（編集画面の「音ハメ」「手で作る」で作成・編集）

```json
{
  "points": [[クリップの頭からの秒, 動画の秒], ...],
  "smooth": 0.08,
  "auto": { ... },
  "accents": [[動画の秒, 強さ, "stop" | "rev"], ...],
  "pairs": [[動画の秒, クリップの頭からの秒], ...],
  "method": "flow"
}
```

- **補間と平滑化**：点のあいだは直線で補間し、点の外は端の傾きでのばします。`smooth`（秒）があれば、その幅で 9 点の平均をとって速さの段差をやわらげます（Attention の `beatwarp.TimeMap` と同じ）。
- **点の値の意味**：**点は動画の秒そのもの**です（`in`・`speed` は使いません。`in` は点が決める頭の秒の写しとして入れておきます）。頭を切ると点がずれて、映る絵は動きません。
- **表示専用フィールド**：`accents`（グラフの橙の線）・`pairs`（緑の丸）は表示用です。描画時は見ません。
- **`auto`（音ハメの設定）**（詳しくは `pyengine/mittler/onbeat.py` の冒頭）：
  - `min`・`max`：速さの下限・上限
  - `lam`：ふだんの速さから離れにくさ
  - `jerk`：なめらかさ
  - `slip`：頭を後ろにずらせる秒
  - `half`：裏拍にも合わせる
  - `end`：終わりを素材の終わりに合わせる
  - `thr`：アクセントのしきい値
  - `smooth`：平滑化の幅（秒）
  - `in`：頭の秒（やり直しても同じ所から始めるため）
  - `in_rng`・`out_rng`：頭・終わりで映してよい動画の秒の範囲
  - `fit`：ふだんの速さを範囲から決める
  - `pins`：必ず通る点 `[[動画の秒, クリップの頭からの秒], …]`
  - `grid_extra`：拍のほかに合わせる秒
  - `until`：音ハメを閉じる秒
  - `note`：メモ

### 2. 表のファイル（文字列、`root` からの相対パス）

- ファイルの中身：`{"table": [[クリップの頭からの秒, 動画の秒], …]}`。
- 表の外は端の値（`np.interp`）で固定され、動画の秒に `in` を足して使います。
- 偽マリアMV の取り込みで使った形式です。編集画面では読み込み専用で、「直せるようにする」で点形式へ写せます（元ファイルはそのまま残り、`from_file` に元のファイル名が入ります）。

### 音ハメの自動計算

- 処理経路：編集画面「音ハメ（自動）」→ サーバー `POST /api/warp/auto {q}` → 描画サーバー `GET /warp?q=` → `pyengine/mittler/onbeat.py`
- 仕組み（Attention ダンスMV の `beatwarp.py` を `pyengine/mittler/beatwarp.py` に取り込んだもの）：オプティカルフローで動きの止まり・切り返し（＝アクセント）を見つけ、タイムラインのビートと順番に組にして、速さの上限・下限の中で「ふだんの速さからの離れ」と「となりとの速さの差」がいちばん小さい付け替えを選びます。
- 動きの解析結果は描く PC の `<作品>/work/beatwarp/` に CSV で保存します。`cv2` が無ければフレーム差分だけで見ます（向きの切り返しは分かりません）。

### 素材のコマのまま読む（`"sample": "source"`）

Attention ダンス動画の取り込みで追加しました（2026-10-21）。

- 素材をそのままの大きさ・fps で頭から読み、`round(素材の秒 × 素材の fps)` のコマを選びます。
- 速さ（`warp` の表の 3 列目、または点の傾き）が `blend_below` より遅いところは、隣のコマと混ぜます。
- 画面へは Pillow の bicubic で 1 回だけ拡大（cover）し、カメラのエフェクト（`camera()` を持つもの。`docs/エフェクトの書き方.md`）のズーム・ずらし・回転も同じ 1 回でかけます。
- `src` は 1 本だけです。指定しないクリップは今までどおり（ffmpeg で画面の大きさ・fps にしてから読む）です。

## クリップ（共通）

すべてのクリップに共通して使えるキーです。

- `id`：作品の中で一意の ID
- `type`：クリップの種類
- `start`・`dur`：開始時刻・長さ（秒）
- `label`：タイムライン上の表示名
- `disabled`：`true` で無効化
- `cut`：カットのラベル。指定すると、そのカットを映しているあいだだけ効きます
- `link`：リンクの印。同じ印のクリップは編集画面で一緒に選択・移動・分割・削除されます（動画とその音 `assets/video_audio/*.wav` など）。描画・書き出しでは見ません
- `grade`：クリップの色（`video`・`image`・`plan` のみ。下）

### 時刻の書き方

エンジンはコマ `n` の時刻 `t = n / fps` を `start <= t < start + dur` で判定します（静止画・プレビュー・書き出しとも同じ。書き出しは並列数によらず `n / fps`）。

- コマ `n` から始めたいクリップの `start` は、**`n / fps` を計算した値そのまま**を書きます（30fps のコマ 20 なら `0.6666666666666666`）。
  - `0.666667` のように丸めた値は `n / fps` より大きくなることがあり、1 コマ遅れて始まります（3 コマに 1 つが該当します）。
- `dur` は「終わりのコマの時刻 − `start`」とし、`start + dur` が終わりのコマの時刻を超えない値にします。
- 編集画面では、移動・伸縮・分割・数値欄で直したクリップをこの書き方にそろえて保存します（触っていないクリップの値は書きかえません）。
- コマに乗せないクリップ（音・歌詞の時刻に合わせたものなど）は、秒の値をそのまま書いてかまいません。

### クリップの色（`grade`、2026-10-31）

```json
"grade": { "b": 1.2, "c": 0.9, "v": 1.1, "s": 1.3 }
```

- パラメータ：明るさ `b`・コントラスト `c`・ビブランス `v`・彩度 `s`。`1.0` で変化なし（省略時は `1.0`）。編集画面のつまみは `0.5〜1.5` です。
- 計算式は色の卓（`grade` エフェクト）と同じ `effects_lib/common/grade.py` です（エンジンはこのファイルをそのまま読み込みます。編集画面の `editor/calc.js` の `gradePixel` と一致することは `tools/smoke_same.py` で確認します）。
- 適用タイミング：エンジンはそのクリップの絵を読んだ直後（`engine.py` の `_clip_frame`：カメラ・音ハメ・速さで決まったそのコマの絵）、**エフェクトより前**にかけます。同じ値の `grade` エフェクトクリップをいちばん下のトラック（最初にかかる位置）に置いたのとビット単位で同じ絵になります（確認済み）。
- カットの色の卓（`grade` エフェクトのクリップ、`cut` にカットのラベル）とは別で、両方かかります（クリップの色 → エフェクト … → カットの色の卓）。
- クリップと一緒に移動・分割・コピーされます。編集画面ではすべて `1` になると `grade` を削除します。`grade` が無い・すべて `1` のクリップは式を通さず、今までと 1 ビットも同じ絵です。
- 動画化予定クリップの `grade` は予定の絵（スタート→エンド・選んだテイク）にかかり、「採用」で配置する映像クリップにも引き継がれます。描画サーバーのサムネ（`/api/thumb`）には付けません。

### クリップの `type` ごとのキー

#### `video`

- `src`：`root` からの相対パス（配列でも 1 本の文字列でも可）
- `in`：素材の何秒目から再生するか
- `speed`：一定の速さ
- `warp`：時間の付け替え＝音ハメ（上）
- `land`：終わりを素材の終わりに合わせる
- `curve`：色のカーブの JSON
- `sample`：`"source"` なら素材のコマのまま読む（上）
- `blend_below`：`sample: "source"` のとき、速さがこれより遅いところは隣のコマと混ぜる
- `upscale`：マスター書き出しのアップスケールをこのクリップだけ変える（`"anime"`・`"real"`）。無ければ作品の `settings.master.upscale` を使う。作品が `"none"` のときは使わない（`"none"` はクリップには書けない）。編集画面の映像クリップ欄「マスター画質」（高画質（アニメ）・高画質（実写））に対応。通常描画・通常書き出しでは見ない
- `grade`：クリップの色（上）

#### `image`

- `src`：画像のパス（`root` からの相対）
- `camera`：`[[秒, 拡大, 中心x 0〜1, 中心y 0〜1], …]`（秒はクリップ頭から）
- `pop`：タイトルカードのように 0.93 倍から弾んで出る（黒地）
- `follow_cam`：`false` ならカメラのエフェクト（揺れ・つつき）を受けない

#### `effect`

- `effect`：`effects/` のファイル名（拡張子なし）
- `params`：エフェクトごとのパラメータ（`docs/エフェクトの書き方.md`）

#### `plan`

使い方は `docs/スターターガイド（人間用）.md` の 5、生成との受け渡しは `docs/H3受け渡し契約.md` を参照してください。

- `start_frame`・`end_frame`：`{src, prompt, takes, activeTake}`
  - `src` は `root` からの相対パス。
  - `prompt` の参照は `@import char(id) as 名前;` など。
  - 絵のエンジンを選ぶなら `engine`（`codex`・`openai`・`nanobanana`。無ければ PC の設定 `mittler.image.engine` → `codex`）。
  - OpenAI の場合は `model`（例：`gpt-image-2.5-sunburst`・`gpt-image-2.5-flare`）・`quality`（`auto`・`low`・`medium`・`high`・`xhigh`・`max`）も指定可能。テイクには `engine`・`model` が残る。
- `video`：`{prompt, engine: "h3-fl2va"｜"h3-ref2va", takes, activeTake, adopted}`
- `upscale`：選んだ動画テイクをマスター書き出しで上げるモデル（映像クリップと同じ。編集画面にはまだ欄が無いので JSON で書く）

#### `subtitle`

- `text`：字幕テキスト（改行で 2 行）
- `style`：`font`・`size`・`color`・`stroke`・`stroke_color`・`stroke_alpha`・`shadow`・`x`・`y`・`align`・`valign` など。無い項目は `settings.subtitle` → 既定を使う
- `speaker`：（任意）話者

#### `tts`

- `character`：キャラ ID
- `engine`：`gemini` ／ `voicevox`
- `text`：セリフ本文（Gemini の演技タグもそのまま書く）
- `gemini`: `{model, voice, style}`・`voicevox`: `{speaker, speedScale…}`（空ならキャラ設定の値）
- `delivery_style`：このシーンの演技（Gemini ではスタイルのあとに ` / ` でつないで送る）
- `tempo`：生成後の速さ `0.5〜2`（ffmpeg の `atempo`。無ければキャラ設定の `tts.tempo`、それも無ければ `1`。2026-11-15）
- `takes`: `[{id, src, dur, engine, text, tempo?, …}]`
- `activeTake`：鳴らすテイク ID
- `gain`（dB）・`in`・`fade_in`・`fade_out`・`fade_in_curve`・`fade_out_curve`（下の `audio` と同じ）

#### `audio`

- `src`：音声ファイル。`src` が無い（`null`）クリップは鳴らない（書き出し・再生とも飛ばす）
- `in`：素材の開始位置（秒）
- `gain`：音量（dB）
- `norm`：素材ごとの大きさそろえ（dB）
- `norm_peak`：`true` で素材全体のピークを 1 にそろえてから適用（numpy の混ぜ方のみ）
- `fade_in`・`fade_out`：フェード時間（秒）
- `fade_in_curve`・`fade_out_curve`：フェードの形（ffmpeg の `afade` の `curve`：`tri`＝直線（既定）、`qsin`＝4 分の 1 サイン、`log`・`exp` など）
- `ramp`：`[始めの dB, 終わりの dB]`
- `music`：Suno の曲（下）

## Blender の 3D のクリップ（エフェクト `blender3d`、2026-11-13）

Blender で描く 3D は、エフェクトトラックに置く**エフェクトのクリップ**（`"effect": "blender3d"`）として扱います（新しいトラック種別は増やさず、重ね順＝トラック順で他のエフェクトと同様に移動・伸縮・パラメータ編集ができます）。作品の `effects/blender3d.py`（`effects_lib/common/blender3d.py` の写し）が必要です。

```json
{ "id": "t_blender3d", "name": "Blender の 3D", "kind": "effect", "effect": "blender3d", "clips": [
  { "id": "logo3d", "type": "effect", "effect": "blender3d", "start": 0, "dur": 5,
    "params": { "scene": "3d/logo.py", "args": { "text": "Mittler" }, "engine": "CYCLES", "samples": 64, "draft_samples": 8, "draft_scale": 0.5,
                "device": "auto", "denoise": true, "transparent": true, "view": "scene", "blend": "over", "opacity": 1 } } ] }
```

| `params` | 中身 |
|---|---|
| `scene` | 場面のファイル（`root` からの相対）：bpy スクリプト `3d/<名前>.py`（`build(scene, args)` と `frame(scene, t, args)`。ひな形は `templates/3d/`）か `.blend`（場面の `frame_start` から `t` 秒のところを描く） |
| `args` | スクリプトに渡す dict（`dur` を書かなければクリップの長さが入る） |
| `engine`・`samples`・`device`・`denoise` | `CYCLES`（既定。`device: "auto"`＝OptiX → CUDA → HIP → CPU）か `EEVEE`、本番のサンプル数 |
| `draft_samples`・`draft_scale` | プレビューの下描き（ためた本番の絵が無いコマ）の品質と大きさ |
| `transparent`・`view` | 背景を透明にする（下の絵に重なる）・色の見え方（`scene`＝場面のまま・`Standard`・`AgX`） |
| `blend`・`opacity` | 重ね方（`over`・`add`・`screen`）・強さ |

- **キャッシュ**：描いた絵は作品の `work/3d/<クリップの id>/<鍵>/<コマ>.png`（RGBA）にためます（`work/` は git に入りません）。
  - 鍵は場面ファイルの中身・`args`・大きさ・fps・品質・Blender の版から生成します（いずれかが変われば描き直します。数値 `3` と `3.0` は同じ値とみなします）。
  - スクリプトが読む外部ファイルだけを直したときは、クリップ欄の「描き直す」を使います。
  - コマ番号はクリップ頭からの番号なので、クリップを移動しても使い回せます。
- **品質と実行**：書き出しは区間の前にまとめて描き、プレビューは下描き、静止画と PNG 保存は本番品質です（`pyengine/mittler/blender.py` の冒頭）。Blender の場所は設定 `mittler.blender.path`（インストールガイドの 12・14）。
- GPU の 3D（`gl_cards3d`・`gl_particles3d`・`gl_lightrays`）も通常のエフェクトクリップです（`docs/エフェクトの書き方.md` の「3D のエフェクト」）。

## Suno の曲（音のクリップの `music`、2026-10-30、機能追加案02 v2）

Suno で作る曲は、音のクリップ（ふつうは音楽トラック、`role: "bgm"`）に `music` として書きます。構造は動画化予定の `video.takes` と同じ形です。
Suno を呼ぶのは Claude Code（AI）だけで、Mittler（サーバー・編集画面）は呼びません。受け渡し手順は `docs/Suno受け渡し契約.md` の「Mittler 側の受け渡し」を参照してください。

```json
{ "id": "music_01", "type": "audio", "start": 0, "dur": 30, "in": 0, "gain": -6, "fade_in": 0, "fade_out": 1, "label": "オープニングの曲",
  "src": "assets/music/music_01_t1.wav",
  "music": {
    "prompt": "疾走感のあるエレクトロスウィング、女性ボーカル、BPM120前後", "lyrics": "", "title": "opening", "style": "electro swing",
    "instrumental": false, "duration": 30,
    "takes": [ { "id": "t1", "suno_id": "6601f139-…", "song_url": "https://suno.com/song/6601f139-…", "title": "opening", "prompt": "（生成のときの全文）",
                 "style": "electro swing", "model": "…", "dur": 30.0, "credits": 5, "created": "…", "sidecar": "assets/music/music_01_t1.suno.json",
                 "analysis": { "status": "complete", "bpm": 72, "key": "A major", "time_signature": 4,
                               "beats": [[0.41, 1], [1.24, 2], …], "sections": [{ "start": 0, "end": 7.9, "label": "A" }, …], "terms": […], "labels": […] },
                 "src": "assets/music/music_01_t1.wav", "format": "wav", "downloaded": "…" } ],
    "activeTake": "t1", "adopted": "t1",
    "adopt": { "take": "t2", "format": "wav", "requested": "…" } } }
```

| キー | 中身 |
|---|---|
| `prompt`・`lyrics`・`title`・`style`・`instrumental`・`duration` | 生成時に Suno へ渡す設定（AI が書き、ユーザーが編集画面で確認・修正）。`prompt`＝曲の説明（Suno の Simple の description）、`lyrics`＝歌詞（書けば Custom）、`duration`＝目標秒数（15〜360。無ければクリップの長さ） |
| `takes` | Suno で作った曲（1 曲＝1 テイク、`id` は `t<n>`）。編集画面（サーバーの `/api/music/take` に届いたもの）が入れる。生成時は**ファイルを取らない**ため `src` は無い。`analysis` は Suno の `audio-analysis` を読みやすくしたもの（`beats` は `[曲の秒, 小節の中の位置 1〜]`、1 が小節の頭） |
| `activeTake` | 最後に届いた／採用したテイク |
| `adopt` | **採用待ち**（ダウンロード待ち）の印。ユーザーが編集画面で「採用」→ ダウンロード用クレジットを 1 つ使うことに OK したもの。AI がファイルを取って納品すると編集画面が消す |
| `adopted` | クリップの `src` に設定しているテイク（採用済み） |

- **採用時の反映**：編集画面がクリップの `src` をそのテイクのファイルに、`in` を `0` に変更します（テイクのほうが短ければ `dur` もテイクの長さに調整）。同時に、解析の拍と構成をメタデータへ入れます。
  - `beats`：「ビート（Suno・…）」
  - `song_sections`：「曲の構成（Suno・…）」
  - どちらも `from_music`（＝クリップの `id`）・`from_suno`（＝Suno の `id`）を持ち、同じクリップのものを入れ直すと置きかわります。
- **再生・書き出し**：`src` だけを参照し、`music` は読みません。`music` を使わない作品への影響はありません。

## 字幕を ASS で焼く（`settings.subtitle.renderer = "ass"`、2026-10-21）

`dialogue-video`（紙芝居・掛け合い動画）と同じ字幕方式です。字幕トラックのクリップ（`text`・`start`・`dur`）から ASS を生成し、ffmpeg の `ass`（libass）で絵のいちばん最後に焼きます（`pyengine/mittler/ass.py`）。

- 静止画・プレビューは 1 コマずつ、書き出しはエンコードの ffmpeg の `-vf` で適用します（どちらも同じ絵になります）。`effects/subtitle.py`（Pillow）はかかりません。
- `settings.subtitle.ass` で既定スタイルを指定できます：
  - ASS の Style 欄：`fontname`・`fontsize`・`primary`・`secondary`・`outline_colour`・`back_colour`（`&HAABBGGRR`）・`bold`…`encoding`
  - その他：`wrap_style`・`scaled_border_and_shadow`・`fontsdir`（`root` からの相対。libass が使う書体のフォルダ。字幕の字だけを置く）・`style_name`
  - 省略項目は `dialogue-video` の既定値（Noto Serif JP 56・下から 65・白っぽい字に半透明の紺の縁と影）になります。
- クリップに `style`（編集画面の字幕欄：`size`・`color`・`stroke`・`stroke_color`・`stroke_alpha`・`shadow`・`shadow_color`・`shadow_alpha`・`margin_v`・`align`・`valign`、`ass`＝Style 欄そのまま）があれば、そのクリップだけ別の Style にします。時刻は 1/100 秒（`round(秒 × 100)`）です。

## numpy の混ぜ方（`settings.audio.mixer = "numpy"`、2026-10-21）

作者の紙芝居の作品の `build.py` の `build_audio` と同じ計算です（`pyengine/mittler/mix.py` の `mix_numpy`）。

1. 素材を ffmpeg で 48 kHz・2ch の `float32` に変換
2. `norm_peak` を適用
3. `in` から `dur` を切り出し
4. 直線のフェード → `ramp` → dB を適用
5. `start` の位置に足す（秒はサンプル数に丸める）
6. ピークが `settings.audio.peak` を超えたら下げる
7. `s16` へ変換

- **足す順はトラックの並び（上から）、トラック内はクリップの並び**です（浮動小数点加算の順まで元と一致させるため）。
- `fade_*_curve` は使いません（直線フェードのみ）。

## メタデータ（`meta`）

```json
{ "id": "m_…", "kind": "…", "name": "表示名", "items": [ ] }
```

| `kind` | `items` の中身と用途 |
|---|---|
| `cuts` | `{label, start, end}`（カット。空でもよい＝全体で 1 カット）。ほかに `lyric`（歌詞）・`togaki`（ト書き）・`page` など（偽マリアの取り込み）、`from_plan`（動画化予定クリップから作ったカット）。描画は `start` の順だけを見る（そのカットは次のカットの頭まで続き、最初のカットより前も最初のカット扱い） |
| `beats` | `[秒, 小節の頭 0/1, 強さ]`（エフェクトの `ctx.beats`） |
| `pulse_grid` | `[秒, 強さ]`（細かい拍＝4 分＋8 分の裏。偽マリアMV の取り込み器が入れる。エフェクトは `pyengine/mittler/helpers.py` の `grid(ctx)` で読む。編集画面には出さない） |
| `sections` | `{start, end, value 0〜1}`（区間の強さ。`ctx.level()`） |
| `lyrics` / `dialogue` / `notes`（ト書き） | `{start, end, text, who?}`（右の「メタデータ」タブで編集可能）。Suno の曲採用で入る歌詞（`from_music`・`from_suno` の付いた `lyrics`、2026-11-15）は、`words: [[始め, 終わり, 字, 置けたか], …]`（単語ごとの時刻。タイムライン秒）と `uncertain`（置けなかった単語の数。あるときだけ）を持つ |
| `song_sections`（曲の構成） | `{start, end, text}`（`text` は Suno 解析の区間ラベル A・B…。同じラベルは同じ素材のくり返し＝サビのことが多い）。Suno の曲採用時に入る。描画は読まない（`sections` の `ctx.level()` とは別） |

### カットとクリップの `cut`（2026-10-31、編集画面のカットの段の道具 `editor/cutmeta.js` の決まり）

クリップの `cut` にはカットのラベルを書きます。描画では「今のカットのラベルと同じ `cut` を持つクリップ」だけを使います（映像は `engine.py` の `_pick_clip`、エフェクトは `active`）。`cut` の無いクリップは時刻だけで決まります。窓が `per_cut` のエフェクト（色の卓 `grade`・偽マリアの光・人のマスクなど）は、頭と長さをカットに合わせておきます。

編集画面でカットを直すと、参照も次のように付け替えます（いずれも 1 回の取り消し対象）。ファイルを手で直すときも同じルールに合わせます。

- **ラベルを変える**：同じラベルの `cut` をすべて新しいラベルへ書きかえる。
- **分ける（時刻 `t` で）**：
  - 後ろの新しいカットに入るクリップ（頭が `t` 以降）は新しいラベルへ付け替える。
  - `t` をまたぐクリップの扱い：
    - `per_cut` のエフェクト：同じ値の写しを新しいカットに作る。
    - そのほかのエフェクト・字幕：同じ時間のまま新しいカット用の写しを作る。
    - 映像・画像：`t` で分ける（後ろの `in`・音ハメの点・画像の `camera` をずらし、映る絵を変えない）。
    - 例外（分けないもの）：音ハメの表のファイル（`warp` が文字列）・`land`・`pop` の画像・動画化予定クリップがまたがるときは分けない。
  - 新しいカットの歌詞・ト書きは空にする。
- **つなぐ・消す**：消えるカットの `cut` を残るカットのラベルへ付け替える。`per_cut` のエフェクトで残るカットにも同じエフェクトがあるもの、および分けたときの写し（同じ値・同じ時間）は消す。
- **境目を動かす**：隣のカットの端も一緒に動かし（すき間・重なりを作らない）、`per_cut` のエフェクトの頭と長さを合わせる。**映像クリップは動かさない**（ずれは編集画面が警告の印で知らせる）。
- **映像をカットに合わせる（ユーザーが押したとき）**：
  - そのカットのラベルの映像・画像クリップのうち、いちばん前のものの頭をカットの頭へ、いちばん後ろのものの終わりを次のカットの頭（最後のカットはカットの終わり）へ合わせる。
  - 頭を `d` 秒動かすときは、`in` を `d × speed`（音ハメの点は点の秒を `−d`、画像は `camera` の秒を `−d`）ずらし、素材の時刻を変えない。
  - 合わせない条件（1 つでも該当すれば何も変えない）：
    - 伸ばして素材の頭より前・終わりより後ろになるとき（終わりを伸ばすのに素材の長さが分からないときも含む）
    - `land`・動画化予定（`plan`）
    - `warp` が文字列（表のファイル）の頭を動かす・終わりを伸ばすとき
    - `pop` の画像の頭を動かす・終わりを伸ばすとき（終わりを縮めるだけなら可）
- **`settings.cuts_on_adopt`（`true`）**：
  - 動画化予定の「採用」で予定クリップの範囲をカットにする（カットが無い場所なら追加、1 つのカットの中なら分割）。
  - ラベルは予定クリップの `label`（先頭の「カット」は外す。無ければ次の番号）、項目に `from_plan` を付ける。置いた映像クリップの `cut` もそのラベルにする。
  - 予定クリップの文（`label`・`video.prompt`）はト書きには入れない。範囲が 2 つ以上のカットにまたがるときは追加せず知らせる。

## キャラ設定（`characters.json`）

```json
{ "characters": [ { "id": "hana", "name": "ハナ", "image": "assets/characters/hana.png", "profile": "人物像・話し方", "color": "#b25ad6",
    "tts": { "default_engine": "gemini",
             "gemini": { "model": "gemini-3.8-flash-tts", "voice": "Kore", "style": "いつもの声の指示" },
```

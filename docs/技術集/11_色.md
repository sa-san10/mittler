# 11 色（カットごとの色合わせ・カーブ・トーンマップ・口パクの色合わせ）

**Mittler に部品あり**：右の「色」タブ（カットごとの明るさ・コントラスト・ビブランス・彩度のスライダー。動かしている間はおおよその色、離すと本物で描き直す）と、映像クリップの `curve`（トーンカーブ）が使えます。
**色の値はユーザーが決めます**（頼まれない限り、AI が勝手に決めないでください）。

## 1. 色の卓（カットごとの色合わせ）
- 生成した動画はカットごとに彩度や明るさがばらつきます。数値で合わせようとするより、人が見ながらスライダーで合わせるほうが早くて確かでした。
- **計算式と適用順**：sRGB のまま、明るさ → コントラスト → ビブランス → 彩度の順に適用します（`effects_lib/common/grade.py`。編集画面のおおよその色も同じ式の `editor/calc.js`）。
  - 光のエフェクトのあと・外周のネオンと文字の前に、映像だけにかけます。
- **自動補正の失敗例**：自動の彩度合わせ（カットごとに彩度を測って倍率をかける方式）は上げすぎや不安定さが出て、結局すべて外しました。自動より手のスライダーが確実です。

## 2. トーンカーブ
- **データ形式**：`{"mode": "luma"|"rgb", "points": [[入力, 出力], …]}`。
  - 点のあいだは行き過ぎない単調な 3 次補間で結びます。`luma` は色味を保ったまま明るさだけを動かします。
- **Mittler の実装**：`pyengine/mittler/lib/curve.py`（映像クリップの `curve`）。確認時は、直す前・直した後・カーブのグラフを並べた画像を作って比較します。

## 3. 口パク版と口パクなし版の色合わせ・トーンマップ
- H3 の `ref2va`（口パク）は `fl2va` より暗く彩度が低くなります（07）。口パクカットを前後のカットに合わせる色合わせが必要です。
- 全体のトーンマップ（タイムラインの `settings` の `tonemap`）は、何種類かを同じコマで並べて比べてから決めます。
- **Mittler の部品**：偽マリアのエフェクト集の `fm_match`（ガンマと彩度）・`fm_light`（光とトーンマップ）が使えます。

## 4. 書き出しの色
- 書き出し時の色空間変換は **BT.709**（`settings.export.video.colors`）を使います。
- 生成した動画は色のタグが無いことがあります。読み込み時も BT.709 として読み込みます（マスク生成の道具や合成の道具でも同じ扱いにしないと色がずれます）。

## 5. 生成した絵の部分の直し
- 絵の一部（口紅のまわり・手元など）だけを直したいとき、絵をまるごと作り直すとほかの箇所にノイズが入ります。直した絵からその部分だけを切り抜き、マスクのふちをぼかして元の絵に合成します。
- 画像生成での部分の直しについては 08 を参照してください（Nano Banana Pro が向いており、直しを重ねないのがコツです）。
